# BOOM / TROX — перенос SEO-каталога на основной WordPress-сайт

## 1. Роль GitHub и боевого сайта

Репозиторий `boomengain-source/boom-site` и GitHub Pages — только staging для разработки, проверки верстки, контента и структуры. Основной поисковый трафик должен идти только на `https://boom-eng.ru/`.

GitHub staging закрыт от поискового обхода через `robots.txt`, чтобы после переноса не создавать конкурирующие дубли страниц на `github.io`.

## 2. Рекомендуемая SEO-структура URL на boom-eng.ru

Не использовать на основном сайте `.html` и не копировать staging-slug буквально. Создать единый раздел `/trox/`.

### Корень

- `/trox/` — основной каталог и вход в TROX-раздел.

### Категории оборудования

- `/trox/fire-smoke-dampers/`
- `/trox/vav/`
- `/trox/air-diffusers/`
- `/trox/cav-air-distribution/`
- `/trox/cleanrooms/`
- `/trox/bibo-safe-change/`
- `/trox/sound-attenuators/`
- `/trox/labcontrol/`
- `/trox/healthcare/`
- `/trox/air-handling-units/`

### Карточки оборудования

По возможности вкладывать модель в категорию:

- `/trox/vav/tvr/`
- `/trox/vav/tvj/`
- `/trox/cleanrooms/tfp/`
- `/trox/bibo-safe-change/ksfs/`
- `/trox/sound-attenuators/ms/`
- `/trox/fire-smoke-dampers/fka2-eu/`
- `/trox/air-handling-units/x-cube/`

Если текущая WordPress-архитектура не позволяет удобно поддерживать вложенные product URL, допустим второй вариант `/trox/products/tvr/`, но на всём сайте должна использоваться одна схема.

### Отраслевые SEO-страницы

- `/trox/solutions/` — хаб отраслевых решений.
- `/trox/solutions/pharma/` — вентиляция фармацевтических производств.
- `/trox/solutions/laboratories/` — вентиляция лабораторий.
- `/trox/solutions/medical/` — вентиляция медицинских учреждений.
- `/trox/solutions/microelectronics/` — cleanroom для микроэлектроники и полупроводников.

Эти страницы должны ссылаться на соответствующие категории и модели оборудования, а категории — обратно на релевантные отраслевые решения.

## 3. Как встроить в существующий WordPress

Не вставлять полный HTML-документ в Gutenberg или Classic Editor.

Нужно сохранить существующие `header.php` и `footer.php`, а из staging переносить только содержимое `<main>...</main>` и соответствующие стили.

Рекомендуется работать через child theme, чтобы обновления основной темы не уничтожили каталог.

### Файлы темы

Создать, например:

```text
/wp-content/themes/boom-child/
  functions.php
  assets/css/trox-catalog.css
  assets/js/trox-catalog.js
  archive-trox_product.php
  single-trox_product.php
  taxonomy-trox_category.php
  page-trox-solutions.php
```

CSS из `styles.css` и локальных `<style>` staging-страниц нужно нормализовать и вынести в `trox-catalog.css`. JS подключать через `wp_enqueue_script`, CSS — через `wp_enqueue_style`.

## 4. Архитектура каталога в WordPress

Для нескольких десятков и будущих сотен моделей не создавать отдельный PHP-шаблон на каждую модель.

Создать Custom Post Type:

- `trox_product`

И taxonomy:

- `trox_category`

Рекомендуемые поля продукта:

- модель;
- полное название;
- категория;
- краткое SEO-описание;
- полное описание;
- технические характеристики;
- изображение;
- официальный URL TROX;
- PDF/документы;
- связанные модели;
- связанные отрасли;
- CTA / форма запроса;
- SEO title;
- meta description.

Удобнее всего реализовать поля через ACF или эквивалентный механизм темы.

## 5. Отраслевые страницы

Отраслевые страницы лучше оставить обычными WordPress Pages, потому что они являются SEO-посадочными, а не карточками оборудования.

Для каждой страницы использовать готовый staging-контент:

- `trox-industry-solutions.html`
- `trox-pharma-ventilation.html`
- `trox-laboratory-ventilation.html`
- `trox-medical-ventilation.html`
- `trox-microelectronics-cleanrooms.html`

В WordPress переносить основной контент и сохранять структуру H1/H2/H3, но использовать глобальную шапку, подвал, формы и breadcrumbs действующего сайта.

## 6. Изображения

Не оставлять критичные изображения только на внешних URL TROX.

Перед публикацией:

1. получить разрешённые к использованию официальные изображения;
2. сохранить их локально в медиатеке WordPress или в `/assets/images/trox/`;
3. конвертировать при необходимости в WebP/AVIF;
4. указать корректные `alt`, `width`, `height`;
5. применять lazy loading ниже первого экрана;
6. не менять пропорции оборудования и не использовать нерелевантные иллюстрации.

## 7. SEO-настройка каждой страницы

Для каждой категории, продукта и отраслевой страницы обязательно проверить:

- уникальный SEO title;
- уникальный meta description;
- один H1;
- логичную структуру H2/H3;
- canonical на собственный URL `boom-eng.ru`;
- хлебные крошки;
- ссылки на родительскую категорию;
- 2–6 релевантных внутренних ссылок;
- CTA на подбор/КП;
- корректный HTTP 200;
- мобильную версию;
- скорость загрузки и Core Web Vitals.

Schema.org:

- `Organization` — глобально;
- `BreadcrumbList` — на внутренних страницах;
- `Product` — только там, где карточка действительно описывает конкретный продукт и заполнены корректные поля;
- `Service` — при необходимости для проектного подбора/поставки, не подменяя Product schema.

## 8. Перенос SEO metadata

Из каждого staging HTML программист/SEO-специалист берёт:

- `<title>` → SEO title;
- `<meta name="description">` → meta description;
- `<h1>` → H1 страницы.

На WordPress эти данные лучше задавать через используемый SEO-плагин (Yoast, Rank Math или другой), а не печатать вручную в шаблоне.

## 9. Внутренняя перелинковка

Минимальная схема:

```text
/trox/
  ↓
категория
  ↓
модель
  ↔
релевантное отраслевое решение
```

Примеры:

- Pharma → Cleanrooms → TFP / TFM → Pressure control → X-CUBE CROFCU.
- Laboratories → LABCONTROL → EASYLAB TCU3 → VAV → PROCONDIF.
- Medical → Healthcare → HEPA → Pressure control → Fire dampers.
- Microelectronics → Cleanrooms → MFPCR → HEPA/ULPA → Pressure control.

Не создавать страницы-сироты без входящих внутренних ссылок.

## 10. Sitemap и robots на основном домене

После переноса GitHub `sitemap.xml` не копировать на основной сайт: он содержит staging URL.

На `boom-eng.ru` sitemap должен генерироваться WordPress/SEO-плагином и содержать только production URL.

В production `robots.txt`:

- не закрывать `/trox/`;
- указать production sitemap;
- закрыть технические страницы, параметры и staging при необходимости.

## 11. Порядок запуска

### Этап A — backup

Сделать резервную копию файлов сайта и базы данных.

### Этап B — тестовый WordPress

Перенести каталог на staging WordPress или закрытый тестовый URL. Тестовую копию держать `noindex`.

### Этап C — шаблоны

Создать CPT/taxonomy, подключить CSS/JS, собрать общий каталог, категории и карточку модели.

### Этап D — импорт контента

Перенести утверждённые категории, товары и отраслевые страницы из GitHub.

### Этап E — техническая проверка

Проверить:

- все URL;
- HTTP status;
- canonical;
- robots;
- title / description / H1;
- breadcrumbs;
- внутренние ссылки;
- изображения;
- формы;
- мобильную версию;
- PageSpeed/Core Web Vitals.

### Этап F — production

Опубликовать на `boom-eng.ru`, открыть индексацию и обновить sitemap.

### Этап G — индексация

Отправить sitemap в:

- Яндекс Вебмастер;
- Google Search Console.

Приоритетные новые посадочные можно дополнительно отправить на переобход/URL inspection.

## 12. Что делать с существующими страницами boom-eng.ru

Перед запуском составить список существующих URL TROX/оборудования.

Если старая страница заменяется новой, настроить `301` со старого URL на максимально релевантный новый URL. Не делать массовый редирект всех старых страниц только на `/trox/`, если существует более точная новая страница.

Не удалять индексируемую старую страницу без проверки её трафика, внешних ссылок и подходящего адреса для 301.

## 13. Что НЕ делать

- Не направлять основной домен на GitHub Pages как конечное SEO-решение.
- Не индексировать одновременно staging и production копии одного контента.
- Не оставлять `.html` staging URL как боевые адреса WordPress.
- Не вставлять целые HTML-документы в редактор WordPress.
- Не создавать десятки независимых PHP-шаблонов для моделей.
- Не оставлять внешние TROX CDN-картинки единственным источником изображения.
- Не создавать дубли `/trox/tvr/`, `/trox-tvr/`, `/trox-tvr.html` и URL с параметрами для одной страницы.
- Не менять URL после индексации без 301 и обновления внутренних ссылок.

## 14. Критерий готовности к запуску

Раздел можно открывать поисковым роботам только после того, как:

1. все ключевые страницы доступны с HTTP 200;
2. нет битых внутренних ссылок;
3. canonical ведут на `boom-eng.ru`;
4. staging закрыт от индексации;
5. production sitemap содержит новые URL;
6. мобильный интерфейс и формы проверены;
7. изображения локализованы и оптимизированы;
8. нет дублирующих title/H1 и случайных `noindex` на production.
