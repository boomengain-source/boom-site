# BOOM / TROX — усиленный протокол визуального QA

**Цель:** не допускать к показу и переносу на production страницы с отсутствующими, нерелевантными, размытыми, увеличенными или сломанными изображениями оборудования.

## Базовое правило

Пять проверок — это не пять одинаковых просмотров. Это пять **разных ворот контроля**, каждое проверяет свой класс дефектов. Страница считается прошедшей QA только при `0 ERROR`; предупреждения по резкости должны быть устранены или отдельно подтверждены.

## Gate 0 — Asset origin / независимость от внешних картинок

После инцидента с X-CUBE вводится обязательное правило: **основные изображения товарных карточек и детальных страниц на проверочном стенде должны загружаться с того же домена, что и сама страница**.

То есть для GitHub Pages допустимы прежде всего:

```text
assets/images/...
```

а не прямые ссылки вида:

```text
https://cdn.trox.de/...
https://www.trox.de/...
https://другой-сайт/...
```

Проверка:

- product image same-origin — `PASS`;
- внешний URL для основной картинки — `ERROR`, даже если он сейчас открывается;
- редирект на внешний CDN — `ERROR`;
- временная signed/transformed URL — `ERROR`;
- внешняя ссылка допустима только как текстовая ссылка «TROX ↗», но не как обязательный визуальный asset страницы.

Причина: внешняя картинка может работать у разработчика, но не загрузиться у пользователя из-за hotlink-защиты, истёкшего URL, региональных ограничений, referrer policy или изменений CDN.

## Gate 1 — Completeness / наличие

Для каждой товарной карточки и детальной страницы:

- обязательно есть содержательное изображение оборудования;
- `<img>` существует в DOM;
- `img.complete === true`;
- `naturalWidth > 0` и `naturalHeight > 0`;
- нет пустого изображения, серой заглушки или legacy `*-product.svg`;
- есть непустой и предметный `alt`;
- карточки без изображения автоматически считаются `ERROR`;
- после hard refresh изображение должно загрузиться повторно без зависимости от browser cache.

На staging доступна автоматическая проверка: к URL добавить `?qa=1`. Внизу страницы появляется панель `Visual QA`, а подробности выводятся в консоль браузера.

## Gate 2 — Sharpness / фактическая резкость

Проверяется **не только наличие файла, но и соотношение исходного и отображаемого размера**.

Для каждого raster image:

```text
source_density = min(naturalWidth / renderedWidth,
                     naturalHeight / renderedHeight)
```

Критерии:

- `< 1.00` — `ERROR`: браузер физически увеличивает растр;
- `1.00–1.24` — `WARN`: недостаточный запас резкости, изображение заменить или уменьшить;
- `>= 1.25` — минимально допустимо для staging;
- `>= 1.50` — целевой уровень;
- для hero / крупных product image на production стремиться к `>= 2.00` для HiDPI/Retina.

Для SVG дополнительно проверяется:

- корректный `viewBox`;
- отсутствие растровой миниатюры, спрятанной внутри SVG;
- отсутствие визуального размытия при 200% zoom;
- объект должен выглядеть как полноценная продуктовая иллюстрация, а не как схематичная заглушка.

**Запрещено:** `width:100%; height:100%` для растровой фотографии, если это приводит к увеличению относительно intrinsic size. Общий CSS должен только уменьшать картинку, но не растягивать её.

Дополнительно изображение смотрится при 100% и 200% zoom: мелкие детали, кромки, текст на приводах и контрастные линии не должны распадаться на крупные пиксели.

## Gate 3 — Semantic / соответствие модели

Для каждой карточки сверить вручную:

- название модели на карточке;
- официальный URL TROX;
- изображённый тип оборудования;
- подпись `alt`;
- соседние карточки — чтобы изображения не были случайно переставлены местами.

Изображение компонента/узла допускается только если подпись ясно говорит, что показан именно этот узел. Нельзя выдавать визуал другого изделия за нужную модель.

## Gate 4 — Layout / адаптив и визуальная геометрия

Каждая ключевая страница проверяется минимум на:

- 1920 px;
- 1440 px;
- 1024 px;
- 768 px;
- 390 px.

На каждой ширине проверить:

- изображение не растянуто и не обрезано случайно;
- карточки не «едут» по высоте/сетке;
- H1/H2 не ломают композицию;
- нет аномальных пустот;
- кнопки и ссылки доступны;
- image box не становится больше, чем оправдано качеством исходника;
- объект визуально центрирован;
- при отключении cache и после hard refresh визуал остаётся на месте.

## Gate 5 — Acceptance / независимый финальный проход

Финальный просмотр делается **с нуля**, не по списку внесённых правок:

1. открыть главный каталог;
2. пройти все категории;
3. открыть минимум одну детальную карточку из каждой категории;
4. отдельно открыть страницы, где менялись картинки;
5. повторить после hard refresh / очистки cache;
6. повторить в другом браузере или приватном окне;
7. проверить `?qa=1` на всех страницах, где есть товарные карточки;
8. проверить, что GitHub Pages deployment относится к текущему HEAD SHA.

Финальный результат фиксируется как:

```text
External critical images: 0
Missing images: 0
Broken images: 0
Legacy placeholders: 0
Upscaled raster ERROR: 0
Sharpness WARN requiring action: 0
Layout ERROR: 0
Wrong-model images: 0
Hard-refresh ERROR: 0
Deployment: SUCCESS for current HEAD
```

## Автоматический runtime QA

На staging откройте любую товарную страницу с параметром:

```text
?qa=1
```

Например:

```text
https://boomengain-source.github.io/boom-site/trox-air-diffusers.html?qa=1
```

Скрипт проверяет товарные карточки на:

- отсутствие изображения;
- ошибку загрузки;
- legacy SVG placeholder;
- пустой `alt`;
- увеличение растра браузером;
- низкий запас разрешения.

**Красная панель = страницу нельзя сдавать. Жёлтая = требуется ручная проверка/замена изображения. Зелёная = автоматические image-gates пройдены.**

Важно: зелёная runtime-панель не заменяет Gate 0. Перед сдачей отдельно проверяется, что критические продуктовые картинки same-origin и находятся в `assets/images/`.

## Правило для production

На `boom-eng.ru` изображения должны храниться локально в WordPress/media или в контролируемом assets-каталоге. Внешние URL TROX не используются как обязательные product images. Перед production:

- получить/скачать разрешённые исходники максимального качества;
- конвертировать в WebP/AVIF без видимой деградации;
- сохранить оригинал/мастер;
- прописать `width`/`height` или `aspect-ratio`;
- hero/LCP не lazy-load;
- остальные изображения — lazy-load;
- повторно прогнать все gates уже на production/staging WordPress.
